# CRSF2: маршрутизация LAN-пар через AmneziaWG

AmneziaWG непосредственно на VDS соединяет пары сетей Radio и Module. Сервер работает как systemd-служба без Docker. Новые пары можно добавлять командой. ESP32 остаются обычными LAN-устройствами: VPN-клиент работает на роутере или отдельном Linux-шлюзе.

Настройки CRSF2 из [технического задания](./inintial/tech_task.pdf) менять не нужно: Module остаётся мастером с постоянным IP `192.168.55.11`, Radio подключается к этому адресу, обмен идёт по UDP `7777`. Между LAN не используется SNAT/masquerade. На VDS открыт только внешний UDP-порт VPN; публиковать UDP `7777` в интернет не требуется.

## Структура Go-команд

Файлы `cmd/setup-server/main.go`, `cmd/deploy-server/main.go` и `cmd/add-pair/main.go` — тонкие точки входа. Пакеты `internal/setupserver`, `internal/deployserver`, `internal/awgservice` и `internal/addpair` отвечают за настройку, нативное развёртывание под systemd, управление службой и добавление клиентских пар.

## Адреса первой пары

| Узел | VPN-адрес | Локальная сеть |
|---|---:|---|
| VDS / AmneziaWG | `10.77.0.1/24` | — |
| Шлюз Radio | `10.77.0.2/32` | `192.168.66.0/24` |
| Шлюз Module | `10.77.0.3/32` | `192.168.55.0/24` |

Сервер рассчитан на Debian/Ubuntu Linux VDS с systemd и `/dev/net/tun`.

## 1. Подготовьте VDS

Установите Go 1.25 или новее. Мастер соберёт зафиксированные версии `amneziawg-go` и `amneziawg-tools` из исходников и установит их на VDS. В облачном firewall и на хосте разрешите входящий UDP-порт сервера (по умолчанию `51820`). Не открывайте `7777` в интернет. Установщик включает IPv4 forwarding и сохраняет его в `/etc/sysctl.d/99-crsf2-routing.conf`.

## 2. Запустите шлюз и создайте первую пару

Подключитесь по SSH к Debian/Ubuntu VDS, поместите каталог проекта на сервер и из его корня выполните:

```sh
go run ./cmd/setup-server
```

Команда устанавливает AmneziaWG на этом VDS и создаёт `crsf2-amneziawg.service`. Требуются права root; войдите на сервер под root перед запуском. Если `config/server.conf` уже создан, установку/запуск можно выполнить отдельно:

```sh
go run ./cmd/deploy-server
```

При миграции со старого Docker-развёртывания сначала остановите контейнер, чтобы освободить UDP-порт: `sudo docker stop crsf2-amneziawg`. После миграции Docker для этого проекта не требуется.

Мастер запросит только:

1. Публичный IPv4-адрес этого сервера.
2. UDP-порт сервера — Enter оставляет `51820`. Укажите свободный порт от `1` до `65535`; мастер проверяет, что UDP-порт можно занять, и повторяет запрос, если он уже используется. Выбранное значение будет записано в `ListenPort` сервера и `Endpoint` клиентских профилей.
3. LAN Radio в формате CIDR — Enter оставляет `192.168.66.0/24`.
4. LAN Module в формате CIDR — Enter оставляет `192.168.55.0/24`.

Откройте выбранный UDP-порт во внешнем и системном firewall VDS. После ввода мастер установит AmneziaWG, создаст ключ сервера и отдельные ключи Radio/Module, запишет конфигурацию, включит systemd-службу и проверит интерфейс `awg0`. Первая пара сохраняется в `config/pairs/first/radio.conf` и `config/pairs/first/module.conf`. Передавайте каждый профиль только соответствующему шлюзу.

После успешного запуска службы мастер выведет готовые команды `scp` с введённым IP VDS и путём проекта на сервере. Выполните их в PowerShell на компьютере с клиентами, чтобы скачать профили в `C:\Users\Motor\Documents\kentucky`; для другого компьютера замените путь назначения в командах.

При повторной настройке остановите службу до запуска мастера командой `sudo systemctl stop crsf2-amneziawg`, чтобы освободить UDP-порт.

Сборка AmneziaWG и ожидание запуска службы прерываются по `Ctrl+C`. Если прервать мастер после архивации старой конфигурации, прежние файлы останутся в `config/setup-backups/<время>/`; проверьте состояние проекта перед повторным запуском.

Повторный запуск `go run ./cmd/setup-server` выполняет полный сброс: конфиги сервера и всех пар заменяются новой конфигурацией первой пары, а systemd-служба перезапускается. Прежние ключи и профили не удаляются, а перемещаются в исключённый из Git каталог `config/setup-backups/<время>/`. Сохраните нужные профили до сброса: старые клиенты после него перестанут подключаться.

Файлы с приватными ключами исключены из Git. На Linux они создаются с правами только для владельца.

Для управления службой используйте `sudo systemctl restart crsf2-amneziawg`, `sudo systemctl stop crsf2-amneziawg` и `sudo systemctl status crsf2-amneziawg`. Логи доступны командой `sudo journalctl -u crsf2-amneziawg -n 100 --no-pager`.

Служба создаёт userspace-интерфейс `awg0` с помощью `amneziawg-go` и устанавливает маршруты для всех `AllowedIPs` из peer-записей.
Служба читает `config/server.conf` по абсолютному пути проекта, заданному при установке. Не перемещайте каталог проекта после развёртывания; если переместили, выполните `go run ./cmd/deploy-server` из нового расположения.

Проверка на VDS:

```sh
sudo awg show awg0
ip route get 192.168.66.73
ip route get 192.168.55.11
```

После подключения клиентов в `awg show` должны появиться handshake и счётчики передачи.

## 3. Добавляйте пары Radio + Module

После настройки первой пары и запуска шлюза из каталога проекта на VDS выполните одну команду, указав уникальное имя пары, LAN Radio, LAN Module и публичный endpoint VDS. `site-02` ниже — условное имя второй площадки: замените его на своё, например `warehouse`, `office` или `branch-02`.

```sh
go run ./cmd/add-pair warehouse 192.168.67.0/24 192.168.56.0/24 vpn.example.com:51820
```

В endpoint указывайте тот же UDP-порт, который задан в `config/server.conf` в `ListenPort` (для стандартной настройки — `51820`).

Имя должно быть уникальным и содержать только строчные латинские буквы, цифры, дефис или подчёркивание. По имени создаётся каталог с профилями — например, для `warehouse`:

```text
config/pairs/warehouse/radio.conf
config/pairs/warehouse/module.conf
```

Команда проверит подсети и конфигурацию сервера, автоматически выделит два свободных VPN-адреса и сгенерирует отдельные ключи для Radio и Module.

Она добавит peer-записи в `config/server.conf`. Если шлюз запущен, команда перезапустит systemd-службу и проверит интерфейс; если служба выключена — сообщит запустить развёртывание командой `sudo go run ./cmd/deploy-server`. Нужны Go 1.25+ и установленные утилиты AmneziaWG.

Клиентские профили содержат приватные ключи, имеют права только для владельца и исключены из Git. Передавайте каждый профиль только соответствующему шлюзу. Подсети новых LAN не должны пересекаться друг с другом, с VPN-сетью или с уже добавленными peer-сетями. Каждая пара по умолчанию маршрутизирует только свою Radio LAN к своей Module LAN.

## 4. Настройте роутеры/шлюзы

Импортируйте профиль соответствующей стороны как **AmneziaWG**. Обычный WireGuard-клиент может не поддерживать параметры AmneziaWG. Для первой пары в клиентских файлах задайте публичный IP/DNS VDS в `Endpoint`; профили, создаваемые командой добавления пар, получают endpoint из аргумента команды.

- Radio peer: удалённая LAN — сеть Module.
- Module peer: удалённая LAN — сеть Radio.
- Включите автоподключение. `PersistentKeepalive = 25` помогает шлюзам за NAT.

Если VPN-клиент установлен на отдельном устройстве в LAN, добавьте на основном роутере статический маршрут к удалённой LAN через LAN-адрес этого устройства. На роутерах разрешите forwarding между LAN и VPN. Не включайте SNAT/masquerade для трафика между парами.

Команда добавления peer не меняет правила firewall хоста. На VDS firewall должен разрешать forwarding между LAN каждой пары в обоих направлениях; добавьте правила для каждой новой пары в используемый постоянный firewall. Например, для первой пары в iptables:

```sh
sudo iptables -I FORWARD 1 -i awg0 -o awg0 -s 192.168.66.0/24 -d 192.168.55.0/24 -j ACCEPT
sudo iptables -I FORWARD 1 -i awg0 -o awg0 -s 192.168.55.0/24 -d 192.168.66.0/24 -j ACCEPT
```

Адаптируйте правила для nftables или другого firewall и сохраняйте их штатным для дистрибутива способом. Не добавляйте для этих LAN правила NAT. Если публичные адреса клиентов постоянны, ограничьте ими входящий UDP-порт, заданный в `ListenPort`.

## 5. Проверьте CRSF2

1. Проверьте handshake командой `awg show awg0`.
2. С компьютера в сети Radio проверьте Module: `ping -n 20 192.168.55.11` в Windows или `ping -c 20 192.168.55.11` в Linux.
3. Проверьте обратный маршрут, firewall и отсутствие NAT.
4. Для проверки CRSF2 наблюдайте Serial Monitor обеих плат на `115200` бод: установленная сессия, `NET ONLINE`, рост сетевых `tx`/`rx` и чтение параметров Nomad. Целевой RTT — менее `250 мс`.

Ping проверяет ICMP, а не UDP или CRSF2. `Test-NetConnection -Port 7777` проверяет TCP и не подходит для проверки UDP-сессии.
